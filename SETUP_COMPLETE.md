## 🚀 Quick Start (Choose One)

### Option A: Automated (Recommended - 5 min)
```bash
# Windows
./quick-setup-secure.bat

# Linux/Mac
chmod +x quick-setup-secure.sh
./quick-setup-secure.sh
```

**What it does:**
- ✅ Checks Node.js installation
- ✅ Creates directories (certs, logs)
- ✅ **Auto-generates random API key**
- ✅ Generates SSL certificates
- ✅ Creates `.env` file
- ✅ Installs dependencies
- ✅ Displays next steps

### Option B: Manual (15 min)
```bash
# 1. Copy config template
cp .env.secure-example .env

# 2. Generate API key
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# Copy output to .env as MCP_API_KEY

# 3. Generate certificates
mkdir -p certs
openssl req -x509 -newkey rsa:4096 -keyout certs/server.key -out certs/server.crt -days 365 -nodes

# 4. Install dependencies
npm install

# 5. Start secure server
node server-secure.js
```

### Option C: PM2 Production (20 min)
```bash
# 1. Run automated setup
./quick-setup-secure.bat (or .sh)

# 2. Edit .env if needed
nano .env

# 3. Install PM2 globally
npm install -g pm2

# 4. Start with PM2
pm2 start ecosystem-secure.config.js

# 5. View logs
pm2 logs revit-mcp-secure
```

## 🔐 Security Configuration

### Minimum (Localhost - Most Secure)
```env
MCP_HOST=127.0.0.1
MCP_API_KEY=<auto-generated>
ENABLE_IP_WHITELIST=false
ENABLE_RATE_LIMIT=true
```
**Use for:** Solo developers, local machines

### Recommended (Office Network)
```env
MCP_HOST=0.0.0.0
MCP_API_KEY=<strong-key>
ENABLE_IP_WHITELIST=true
WHITELIST_IPS=192.168.1.0/24
ENABLE_RATE_LIMIT=true
RATE_LIMIT_REQUESTS=200
```
**Use for:** Small teams

### Enterprise (VPN Protected)
```env
MCP_HOST=127.0.0.1
MCP_API_KEY=<rotated-monthly>
ENABLE_IP_WHITELIST=true
WHITELIST_IPS=vpn-gateway-ip
ENABLE_RATE_LIMIT=true

```
**Use for:** Large organizations

## 🔑 Using the API Key

### In Claude Desktop Config
```json
{
  "mcpServers": {
    "revit-mcp": {
      "url": "https://your-server:3000",
      "env": {
        "Authorization": "Bearer YOUR_API_KEY_HERE"
      }
    }
  }
}
```

### Testing with curl
```bash
# Get API key from .env
API_KEY=$(grep MCP_API_KEY .env | cut -d'=' -f2)

# Test health (no auth needed)
curl -k https://localhost:3000/health

# Test status (auth required)
curl -k https://localhost:3000/status \
  -H "X-API-Key: $API_KEY"

# Both methods work
curl -k https://localhost:3000/status \
  -H "Authorization: Bearer $API_KEY"
```

## 🚨 Important Reminders

### DO ✅
- Keep `.env` file secret (not in git)
- Use strong API keys (32+ chars, auto-generated)
- Rotate API keys every 90 days
- Monitor logs for suspicious activity
- Use Let's Encrypt in production
- Update Node.js regularly
- Enable IP whitelist when possible

### DON'T ❌
- Share API key via email/chat
- Commit `.env` to git repository
- Use self-signed certificates in production
- Set MCP_HOST=0.0.0.0 without firewall
- Disable rate limiting without reason
- Use weak or short API keys
- Run without HTTPS

## 💬 FAQ

**Q: Do I have to use the secure version?**  
A: For production/shared access, yes. For localhost-only development, the basic version works.

**Q: Can I keep both versions running?**  
A: Yes, test secure version on a different port first.

**Q: What if I lose my API key?**  
A: Check `.env` file. If completely lost, generate a new one.

**Q: How do I rotate API keys?**  
A: Generate new key → update `.env` → restart server → update Claude config.

**Q: Can I use the same API key for multiple machines?**  
A: Yes, but not recommended. Use separate keys per machine.

**Q: Is self-signed certificate OK?**  
A: For development, yes. For production, use Let's Encrypt.
